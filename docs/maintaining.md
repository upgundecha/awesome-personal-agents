# Maintaining the list

Review suggestions for scope, evidence, usefulness, and duplication. Check the canonical repository's license and minimum **1,000 GitHub stars** for each open-source addition. Review maintenance activity, supported capabilities, pricing, and availability quarterly.

Run `npm ci --ignore-scripts` and `npm run lint` after edits. Inspect scheduled link failures weekly; transient rate limits or bot protection do not prove abandonment. Review Dependabot updates before merging.

## Keep the documents consistent

Update the README entry, selection-guide comparison, and affected shortlists together. Keep each category alphabetized and preserve preview and human-assistance labels. Record the date verified. Mark missing evidence Unknown rather than asserting a feature is unsupported.

Current features and roadmap promises must remain separate. Star counts establish eligibility, not task reliability or security. Open-source, self-hosted, free, and paid are distinct dimensions.

## Awesome directory eligibility

The Awesome format and badge do not imply endorsement or inclusion in the central directory. Before proposing this list there, read its current eligibility and contribution rules, including age and AI-generated-content requirements.

- [Creating a list](https://github.com/sindresorhus/awesome/blob/main/create-list.md)
- [Submission checklist](https://github.com/sindresorhus/awesome/blob/main/pull_request_template.md)
- [Awesome lint](https://github.com/sindresorhus/awesome-lint)

`npm run lint` runs content checks without the repository-metadata rule. `npm run lint:full` additionally checks GitHub metadata and may require API access. A passing lint result does not establish directory eligibility.

## Donations

The Sponsor button is configured in `.github/FUNDING.yml` for GitHub Sponsors and Buy Me a Coffee. Keep README Support links consistent. Funding links do not determine product inclusion.
